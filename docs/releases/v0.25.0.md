# Phoenix OS 0.25.0

- **Released:** 2026-07-25
- **Status:** Accepted
- **Specification:** [RFC-0025](../rfcs/RFC-0025-secure-inbound-event-gateway-and-external-event-sources.md)

Phoenix OS 0.25.0 adds an opt-in secure inbound event gateway for external
systems that need to submit reviewed events into the Phoenix Event Bus. The
release preserves Phoenix OS 0.24.0 behavior when inbound configuration is
omitted.

## Highlights

- Reviewed `InboundEventSchema` and `InboundEventNormalizer` registrations form
  the explicit trust boundary between external JSON and internal Event Bus
  contracts.
- Sources select exactly one authentication mode: versioned HMAC-SHA-256 through
  exact leased `SecretRef` versions or RFC-0023 service-account authentication.
- Durable replay reservations, source-event idempotency, normalized payloads,
  accepted-event identity, and stable receipts commit atomically.
- Exact active-source routes reuse the existing Control Plane listener without
  creating a second socket.
- Runtime-owned publication is asynchronous and at-least-once, with bounded
  deterministic retry, interrupted-work recovery, dead letter, and redrive.
- Maintainer Dashboard routes and optional concrete-resource service-account
  administration remain separate from external event submission authority.
- `RuntimeAssembler` owns optional repository composition, schema registration,
  recovery, workers, route synchronization, startup, shutdown, and rollback.

## Security

- Inbound events are disabled by default and create no implicit source, route,
  schema, key, service-account grant, repository, worker, or network permission.
- Raw request bodies are never published directly to the Event Bus and are not
  retained as the durable trusted contract.
- HMAC and service-account credentials are mutually exclusive per request;
  browser cookies, CSRF proofs, and human step-up evidence are rejected on
  source-submission routes.
- HMAC verification binds the exact body digest, source, request identifier,
  source-event identifier, timestamp, nonce, and exact key version.
- Replay evidence and source-event conflicts survive restart with State
  Store-backed repositories, while public authentication failures remain
  generic and enumeration-resistant.
- Disabled and revoked sources have no active ingress route. Remote ingress
  inherits the reviewed TLS, proxy, Host, CIDR, connection, request, and
  admission controls of the shared Control Plane listener.
- Human administration, machine administration, and event submission require
  independent exact permissions and fail closed when their optional security
  boundaries are absent.

## Compatibility and migration

Existing webhook subscriptions are not converted into inbound sources. Existing
service accounts receive no inbound scopes or source resources automatically.
No source, route, schema, HMAC key, credential, replay record, accepted event,
repository, worker, or network permission is created during upgrade.

See the staged
[v0.24.0 to v0.25.0 migration guide](../migrations/v0.24.0-to-v0.25.0-inbound-events.md).

## Release validation

```bash
python scripts/check_webhook_release.py
python scripts/check_inbound_release.py
```

The inbound gate reruns contracts, codecs, repositories, authentication, replay,
idempotency, admission, HTTP, secure transport, publication, recovery,
administration, service-account, Runtime integration, and release-metadata
suites. It builds and inspects a wheel and sdist, rebuilds from the sdist, and
installs both wheels in isolated offline environments without source-tree
imports.

The full repository quality gate is:

```bash
ruff check .
ruff format --check .
mypy
pytest
python scripts/check_webhook_release.py
python scripts/check_inbound_release.py
```
