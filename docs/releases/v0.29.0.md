# Phoenix OS 0.29.0

**Released:** 2026-08-11

Phoenix OS 0.29.0 implements RFC-0029 secure multi-agent coordination and
delegation as an explicit opt-in extension to the v0.28 agent and durable-agent
subsystems.

Release publication uses tag `v0.29.0`, wheel and sdist assets, and
`SHA256SUMS`.

## Highlights

- Server-owned reviewed child-agent registration and exact `agent.delegate`
  authorization for concrete parent/child edges.
- Phoenix-owned immutable lineage, finite recursion, cycle rejection, and stable
  `DelegationId` to child-run identity.
- Finite fan-out, total-child, concurrency, queue, deadline, child input/result,
  aggregation, and root-budget limits.
- Child results remain bounded untrusted data and deterministic aggregation never
  creates policy or executable authority.
- Parent cancellation propagation, finite Runtime shutdown, and no detached child
  lifecycle in RFC-0029 v1.
- Optional durable parent/child linkage, restart-safe child identity, persistent
  lifetime budget accounting, exclusive recovery claims, and explicit indeterminate
  reconciliation.
- Named multi-agent release gate with wheel/sdist inspection, sdist wheel rebuild,
  and isolated offline installation smoke tests.

## Security

Delegation creates work, never authority. A parent does not transfer its permissions,
approvals, credentials, model grants, tool grants, or policy decisions to a child.

Every delegation requires fresh exact `agent.delegate` authorization, and every
child is independently admitted from current server-owned registry/configuration.
Existing RFC-0026 model and RFC-0027 tool/run authority remains independent.

Delegation cannot increase the root run's total configured budget. Completing a
child releases concurrency capacity but does not restore historical lifetime budget,
fan-out, or total-child allowance. Durable restart preserves that accounting.

One `DelegationId` binds to at most one child run. Recovery never silently allocates
a replacement child. A child persisted as `RUNNING` across process loss becomes
`INDETERMINATE` and is not replayed automatically.

Child output is untrusted data. Prompts, child input/output, raw results,
credentials, approvals, secret references, provider orchestration objects, external
response bodies, and raw exceptions remain excluded from content-free operational
surfaces.

RFC-0029 grants no generic shell, filesystem, network, browser, desktop, or
operating-system authority and is not a hostile-code sandbox for installed adapters.

## Compatibility and migration

When coordination configuration is omitted, Phoenix OS preserves v0.28.0 behavior.
Upgrade creates no delegation, child, coordination store, worker, permission,
approval, credential, model call, tool call, or external access automatically.

Follow the staged
[v0.28.0 to v0.29.0 multi-agent migration guide](../migrations/v0.28.0-to-v0.29.0-multi-agent.md)
for disabled-first installation, reviewed registration, exact policy, conservative
limits, restart canaries, durable recovery validation, safe observation, and
disable-first rollback.

## Architecture decisions

RFC-0029 is supported by four accepted records:

- [ADR-0048](../adrs/ADR-0048-delegation-creates-work-never-authority.md) —
  delegation creates work and never transfers parent authority.
- [ADR-0049](../adrs/ADR-0049-monotonic-root-budget-reservation.md) —
  monotonic lifetime root budget and child-capacity reservation.
- [ADR-0050](../adrs/ADR-0050-phoenix-owned-delegation-lineage.md) —
  Phoenix-owned lineage and stable delegation-to-child identity.
- [ADR-0051](../adrs/ADR-0051-runtime-owned-child-lifecycle-and-recovery.md) —
  Runtime-owned bounded child lifecycle and fail-closed recovery.

The formal review is
[`RFC-0029-multi-agent-threat-model-review.md`](../security/RFC-0029-multi-agent-threat-model-review.md).

## Release validation

The release must pass:

```text
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
python scripts/check_webhook_release.py
python scripts/check_inbound_release.py
python scripts/check_inference_release.py
python scripts/check_agent_release.py
python scripts/check_durable_agent_release.py
python scripts/check_multi_agent_release.py
```

The multi-agent gate validates RFC-0029 regression, migration, ADR, security-review,
and release suites; inspects wheel and sdist metadata and contents; rejects unsafe
archive paths and sensitive files; rebuilds a wheel from the validated sdist; and
installs both wheel forms with `--no-deps --no-index` in isolated offline
environments before executing the packaged coordination surface without source-tree
imports.
