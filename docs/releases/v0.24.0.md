# Phoenix OS 0.24.0

- **Released:** 2026-07-24
- **Status:** Accepted
- **Specification:** [RFC-0024](../rfcs/RFC-0024-durable-signed-webhooks-and-event-subscriptions.md)

Phoenix OS 0.24.0 adds an opt-in durable signed webhook subsystem for reviewed
Event Bus events. The release preserves Phoenix OS 0.23.0 behavior when webhook
configuration is omitted.

## Highlights

- Reviewed serializers form the explicit disclosure boundary between internal
  Event Bus payloads and external webhook contracts.
- Canonical immutable delivery envelopes provide stable identifiers,
  source-event deduplication, payload digests, and at-least-once delivery.
- Versioned HMAC-SHA-256 signing leases exact `SecretRef` versions without
  persisting plaintext key material.
- State Store-backed repositories preserve subscription lifecycle, retry,
  recovery, and dead-letter history across Runtime recreation.
- Deterministic bounded retry, global and per-endpoint concurrency, interrupted
  attempt recovery, and explicit redrive share one immutable attempt history.
- Maintainer Dashboard routes and optional service-account routes provide
  separate fail-closed administration models.
- `RuntimeAssembler` owns optional construction, startup ordering, recovery,
  Event Bus subscription, shutdown, and repository lifecycle.

## Security

- Webhooks are disabled by default and create no implicit endpoint, subscription,
  signing key, Event Bus export, or outbound-network authority.
- Only explicitly registered serializers may produce deliverable payloads.
- Signing secrets, signature headers, canonical bodies, endpoint paths, raw
  response bodies, and internal exception details are excluded from safe views.
- Every attempt re-resolves DNS, requires all resolved addresses to pass policy,
  pins the admitted address, preserves the TLS hostname, rejects redirects,
  ignores ambient proxies, and enforces bounded I/O.
- Machine administration requires exact `webhook.*` scopes, the concrete
  `webhooks` resource, replay-protected evidence, and deny-by-default policy.
- Browser credentials are rejected at the machine boundary.

## Compatibility and migration

Existing Event Bus subscribers are not converted into webhook subscriptions.
Existing jobs are not reclassified as webhook deliveries. No signing key,
subscription, endpoint, or outbound permission is created automatically.

See the staged
[v0.23.0 to v0.24.0 migration guide](../migrations/v0.23.0-to-v0.24.0-webhooks.md).

## Architecture decisions

- [ADR-0001](../adrs/ADR-0001-explicit-webhook-serializers-and-durable-envelopes.md)
  — explicit serializers and canonical durable envelopes;
- [ADR-0002](../adrs/ADR-0002-versioned-webhook-signing-keys.md)
  — exact versioned signing keys;
- [ADR-0003](../adrs/ADR-0003-fail-closed-webhook-egress.md)
  — fail-closed egress and SSRF controls;
- [ADR-0004](../adrs/ADR-0004-bounded-webhook-retry-and-redrive.md)
  — one bounded history across retry, recovery, and redrive;
- [ADR-0005](../adrs/ADR-0005-opt-in-webhook-runtime-and-administration.md)
  — opt-in Runtime ownership and separate administration models.

## Release validation

```bash
python scripts/check_webhook_release.py
```

The gate reruns compatibility, signing, SSRF, recovery, management, replay, and
release-metadata suites. It builds and inspects a wheel and sdist, rebuilds from
the sdist, and installs both wheels in offline isolated environments.

The full repository quality gate is:

```bash
ruff check .
ruff format --check .
mypy
pytest
python scripts/check_webhook_release.py
```
