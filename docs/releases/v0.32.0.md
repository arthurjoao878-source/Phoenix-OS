# Phoenix OS 0.32.0

**Release candidate:** 2026-08-19

Phoenix OS 0.32.0 implements RFC-0032 secure host automation and desktop control as
an explicit opt-in extension to the v0.31.0 agent, workspace, memory, multi-agent,
durable-agent, and inference runtime.

Planned publication uses tag `v0.32.0`, wheel and sdist assets, and `SHA256SUMS`.

## Highlights

- OS-neutral public host contracts with a reviewed Windows v0.32.0 adapter and
  migration-free behavior when host automation is omitted.
- Fresh independent `host.process.list`, `host.window.list`, `host.app.launch`,
  `host.window.focus`, `host.app.close`, `host.clipboard.write`, and
  `host.clipboard.read` authorization.
- Server-owned `HostApplicationId` profiles for launch with no arbitrary executable,
  command line, working directory, environment mutation, shell, or elevation authority.
- Phoenix-owned opaque process/window identities bound to one host and finite
  `HostEpoch`, with native PID/HWND values kept behind the adapter boundary.
- Immediate exact target revalidation for window focus and application close, with
  graceful-close-only semantics and no keyboard, mouse, or force-kill authority.
- Independently authorized bounded Unicode text clipboard read/write with read disabled
  by default and no file/image/HTML/Rich Text/binary clipboard surface.
- Runtime-owned lifecycle, content-free observability/administration, manual real-Windows
  dogfood, and isolated offline wheel/sdist package validation.

## Security

Desktop state is data; host effects require fresh authority.

Observed process/window state, application labels, window titles, clipboard text, model
output, tool results, prior enumeration, prior approvals, and adapter state remain
untrusted data and never reconstruct Phoenix authority.

Model-originated host work retains independent RFC-0027 `tool.invoke` authorization in
addition to the exact current `host.*` authorization for each host operation. One host
action never implies another.

Launch resolves only trusted server-owned application profiles. The v0.32.0 surface has
no generic shell, PowerShell, arbitrary executable selection, arbitrary command line,
working-directory selection, environment mutation, elevation, keyboard/mouse injection,
force kill, or generic administrator authority.

Process/window identities are opaque Phoenix identifiers rather than raw native handles.
Focus and close revalidate the exact native target immediately before effect admission and
fail closed on stale identity, changed ownership, changed host epoch, vanished targets, or
unsafe desktop/session conditions.

Effectful operations are never transparently retried after admission. If Phoenix loses
certainty after an admitted external effect, the outcome is indeterminate rather than
automatically replayed or represented as rolled back.

Clipboard content, window titles, native identifiers, executable paths, prompts, and raw
OS failures remain absent from routine operational telemetry and safe public failures.

## Compatibility and migration

When host-automation configuration is omitted, Phoenix OS preserves v0.31.0 behavior.
Upgrade creates no host service, Windows adapter, native handle, process/window
enumeration, application launch profile, clipboard access, host tool, permission,
approval, worker, or desktop effect automatically.

Existing `agent.run`, `model.infer`, `tool.invoke`, `workspace.*`, `memory.*`,
delegation, service-account, and other pre-v0.32 authority remain independent from
`host.*`.

Windows is the only concrete v0.32.0 host adapter. Explicit Windows-adapter configuration
on an unsupported platform fails safely; omission remains a no-op.

Follow the staged
[v0.31.0 to v0.32.0 secure host-automation migration guide](../migrations/v0.31.0-to-v0.32.0-secure-host-automation.md)
for disabled-first rollout, bounded discovery, exact policy, configured application
profiles, clipboard controls, manual Windows dogfood, and disable-first rollback.

## Architecture decisions

RFC-0032 is supported by four accepted records:

- [ADR-0060](../adrs/ADR-0060-host-state-is-data-effects-require-fresh-authority.md) -
  desktop state remains data and every host effect requires fresh exact authority.
- [ADR-0061](../adrs/ADR-0061-server-owned-configured-application-profiles.md) -
  application launch resolves server-owned reviewed profiles rather than model-selected
  executables or command lines.
- [ADR-0062](../adrs/ADR-0062-opaque-phoenix-host-identities.md) -
  process/window authority uses opaque Phoenix identities instead of raw PID/HWND values.
- [ADR-0063](../adrs/ADR-0063-immediate-ui-toctou-revalidation.md) -
  interactive window effects immediately revalidate the exact native target and fail
  closed instead of retargeting.

The formal review is
[`RFC-0032-host-automation-threat-model-review.md`](../security/RFC-0032-host-automation-threat-model-review.md)
and records all fifty-six security invariants, release-candidate evidence, and residual
risks.

## Release validation

The release candidate must pass:

```text
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
python scripts/check_webhook_release.py
python scripts/check_inbound_release.py
python scripts/check_inference_release.py
python scripts/check_agent_release.py
python scripts/check_durable_agent_release.py
python scripts/check_multi_agent_release.py
python scripts/check_agent_memory_release.py
python scripts/check_agent_workspace_release.py
python scripts/check_host_automation_release.py
```

The host-automation gate validates RFC-0032 regressions, migration, ADR, security review,
release-candidate metadata, wheel and sdist contents, archive path safety, required
host-automation package files, and package metadata. It rebuilds a wheel from the
validated sdist and installs both wheel forms with `--no-deps --no-index` in isolated
environments before exercising deterministic packaged host contracts, policy/service
wiring, process discovery, and clipboard write/read without source-tree imports or native
desktop effects.

Real Windows effects remain a separate manual dogfood gate:

```text
python scripts/dogfood_host_automation_windows.py --confirm-real-effects
```

That reviewed run completed process/window discovery, configured Notepad launch, exact
window focus, bounded clipboard write/read with baseline restoration, and one graceful
close without transparent effect retry.
