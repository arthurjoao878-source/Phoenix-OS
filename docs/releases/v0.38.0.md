# Phoenix OS 0.38.0

**Release candidate finalized:** 2026-09-03

**Publication:** pending the normal v0.38.0 release authorization, final-version
artifact build, tag, and publication gates.

Phoenix OS 0.38.0 accepts RFC-0038 secure real-model provider execution and
integrated agent dogfood hardening while preserving the provider-neutral default.
Release publication remains separate and occurs only after the normal authorization,
merge, post-merge CI, final-version artifact, tag, and publication gates.

## Highlights

- Production RFC-0027 model turns execute real inference through the reviewed RFC-0026
  boundary instead of a parallel provider path.
- The reviewed Ollama adapter uses explicit immutable provider/model bindings, loopback
  endpoint policy, bounded complete/streaming translation, bounded usage/finish metadata,
  and optional reviewed model revision/digest validation.
- Provider-native request options are allowlisted and bounded. Unknown options do not
  become ambient endpoint, credential, network, device, context, or model-management
  authority.
- Real agent turns use the Phoenix-owned structured turn envelope and terminate as one
  final result or one tool proposal. Mixed outcomes, multiple proposals, unknown tools,
  and malformed arguments fail closed before normal authorization/execution.
- Development, research, and desktop dogfood profiles narrow existing Phoenix authority.
  They do not add unrestricted shell/filesystem access or autonomous commit, push, merge,
  tag, release, provider-installation, or model-management authority.
- Durable real-provider attempts preserve current provider/model/profile/tool/schema/policy
  revalidation, original deadlines and finite budgets, cancellation continuity, and the
  no-transparent-replay rule for possibly started external effects.
- Real-provider dogfood records content-free operational evidence and hardens provider
  health diagnostics without persisting prompts, model output, tool payloads, workspace
  contents, memory contents, browser contents, clipboard contents, or credentials.
- Mandatory CI remains deterministic and network-free. Real/paid/provider canaries remain
  explicit operational procedures outside mandatory CI.

## Security

Model output is data, not authority. A provider response cannot authorize its own tool,
endpoint, credential, policy, profile, model, or resource expansion. Tool proposals
continue through the normal RFC-0027 validation, authorization, approval, and execution
path.

The local reference provider is constrained to reviewed loopback policy and explicit
provider/model configuration. Phoenix does not automatically install providers, download
models, mutate provider model inventory, kill/restart provider processes, follow ambient
proxy/redirect configuration, or turn provider discovery into authorization.

There is no automatic local-to-cloud fallback. There is no transparent retry after
provider inference may have started. Missing provider/model availability, malformed
provider output, revision mismatch, timeout, cancellation, or an indeterminate external
attempt remains a controlled failure/recovery condition rather than permission to switch
providers or replay an uncertain effect.

Caller parameters cannot amplify trusted deployment resource limits. Advertised provider
context size does not override the smaller Phoenix context/output budgets selected by the
trusted deployment.

No hosted-provider integration was added during RFC-0038 Slice 6 because no concrete
hosted provider and credential were selected. If one is added later, it remains subject
to the RFC-0026 boundary and exact Phoenix secret-leasing requirements.

## Compatibility and migration

With real-provider and dogfood configuration omitted, existing deterministic inference,
agent execution, Runtime composition, and v0.37 durable/recovery behavior remain valid.
No provider process is contacted, no model is installed, no credential is created, no
new tool is registered, and no additional authority is granted.

The provider-neutral package keeps no mandatory runtime dependency. Provider-specific
integration remains an explicit composition boundary rather than an automatic package or
provider-discovery mechanism.

See
`docs/migrations/v0.37.0-to-v0.38.0-real-provider-dogfood.md`
for provider activation, model binding, agent-tool behavior, durable recovery, dogfood,
operator, rollback, and release-gate guidance.

This release note was prepared while the package remained at `0.37.0` during the earlier
Slice 7 gates. The package changed to `0.38.0` only in the dedicated version-finalization
step after the preceding gates and documentation evidence were green.

## Dogfood and operations

Operators enabling the local Ollama reference provider should:

- install and operate Ollama separately from Phoenix;
- explicitly select the reviewed loopback endpoint and provider/model binding;
- use a conservative finite context/output budget and raise it only after measured local
  stability evidence;
- configure a reviewed model revision/digest when the provider exposes suitable evidence;
- keep provider/model inventory and process lifecycle under operator control;
- run real-provider canaries explicitly outside mandatory CI;
- preserve content-free dogfood receipts and avoid persisting prompts or model/tool data;
- treat provider/model disappearance, revision drift, cancellation, restart, and
  indeterminate attempts as fail-closed operational cases rather than fallback/retry
  triggers.

The initial development/research/desktop profiles remain intentionally narrow. Dogfood
does not authorize unrestricted repository writers, shell/PowerShell, arbitrary
filesystem operations, Git lifecycle mutations, or release publication.

## Release validation

The v0.38.0 finalization requires the existing project gates plus RFC-0038-specific
evidence, including:

```text
scripts/check.ps1
RFC-0038 deterministic provider/model-turn tests
python scripts/check_reliability_release.py
real development/research/desktop dogfood checklist
wheel + sdist build validation
isolated offline wheel installation
provider/model/API-independent package import and normal tests
```

The deterministic provider/model-turn surface remains provider-free. Normal tests and CI
do not require Ollama, model weights, hosted-provider credits, or provider API secrets.
Real-provider canaries are separate explicit procedures and are not converted into
mandatory CI dependencies.

The pre-version-bump Slice 7 artifact gate intentionally validates `0.37.0` wheel/sdist
contents before the dedicated version bump. Final publication artifacts must be rebuilt
from the authorized `0.38.0` release state and pass the normal release authorization and
artifact gates; pre-bump gate artifacts are not publication artifacts.
