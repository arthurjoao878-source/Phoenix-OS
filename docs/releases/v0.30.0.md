# Phoenix OS 0.30.0

**Release candidate:** 2026-08-12

Phoenix OS 0.30.0 implements RFC-0030 secure agent memory and context retrieval as
an explicit opt-in extension to the v0.29 agent, durable-agent, and multi-agent
subsystems.

The release candidate is prepared for publication as tag `v0.30.0`, wheel and sdist
assets, and `SHA256SUMS` only after every final gate is green.

## Highlights

- Phoenix-owned `MemoryId`, namespace, and exact run/agent/principal scopes with no
  implicit parent/child or global sharing.
- Independent fresh `memory.search`, `memory.read`, `memory.write`,
  `memory.delete`, and `memory.admin` authorization.
- Explicit bounded writes with immutable provenance, optimistic versions, finite
  retention, expiry, and tombstone anti-resurrection semantics.
- Deterministic bounded lexical retrieval with authoritative source-record
  revalidation before disclosure.
- Provenance-preserving `MemoryContextBlock` injected only as explicitly untrusted
  retrieved data without authority promotion.
- Optional provider-neutral semantic retrieval and a derived reference index that
  stores candidate identity/version/digest plus vector data rather than record
  content.
- Runtime-owned bounded recovery, cleanup, provider deadlines, finite shutdown,
  startup self-cleanup, and content-free observation/administration.
- Named agent-memory release gate with wheel/sdist inspection, sdist wheel rebuild,
  and isolated offline installation smoke tests.

## Security

Memory informs work, never authority. Remembered content, provenance, metadata,
historical permissions, approvals, credentials, tokens, grants, policy fragments,
or prompt injection never reconstruct current Phoenix authority.

Every memory action is independently authorized against the current exact resource.
Existing `agent.run`, `model.infer`, `tool.invoke`, `agent.delegate`,
`agent.resume`, and `agent.reconcile` permissions do not imply memory access.

Phoenix derives scope identity from trusted server configuration or authenticated
context. Model content cannot widen the namespace/scope, and memory is not implicitly
shared across agents, principals, runs, parents, or children.

Writes are explicit. Phoenix does not automatically persist every prompt, response,
tool result, conversation, chain-of-thought, or hidden reasoning. Secrets remain
behind the RFC-0011 boundary rather than becoming ordinary remembered content.

Retrieved text remains untrusted USER-level context. Prompt injection in memory
cannot authorize a model, tool, approval, delegation, credential, policy mutation,
or another memory operation.

The source store remains authoritative. Derived lexical/semantic indexes cannot
override exact record version/digest, deletion, expiry, tombstones, or current scope.
Stale, delayed, wrong-scope, wrong-version, and wrong-digest candidates are rejected
before disclosure.

Logs, events, administration, and public failures exclude memory text, query text,
embeddings, credentials, approvals, secrets, provider bodies, and raw exceptions.
RFC-0030 grants no generic shell, filesystem, network, browser, desktop, or
operating-system authority and is not a hostile-code sandbox for installed adapters.

## Compatibility and migration

When memory configuration is omitted, Phoenix OS preserves v0.29.0 behavior.
Upgrade creates no memory record, store, index, provider call, worker, context,
permission, approval, credential, model call, tool call, delegation, or external
access automatically.

Follow the staged
[v0.29.0 to v0.30.0 agent-memory migration guide](../migrations/v0.29.0-to-v0.30.0-agent-memory.md)
for disabled-first installation, exact scope/policy, conservative limits, explicit
writes, isolation canaries, poisoning tests, semantic-provider review, restart
recovery, safe operations, and disable-first rollback.

## Architecture decisions

RFC-0030 is supported by four accepted records:

- [ADR-0052](../adrs/ADR-0052-memory-informs-work-never-authority.md) — remembered
  content informs work but never becomes Phoenix authority.
- [ADR-0053](../adrs/ADR-0053-phoenix-owned-exact-memory-scopes.md) — exact
  Phoenix-owned run/agent/principal scopes without implicit sharing.
- [ADR-0054](../adrs/ADR-0054-authoritative-memory-records-derived-indexes.md) —
  source records remain authoritative while retrieval indexes are derived.
- [ADR-0055](../adrs/ADR-0055-finite-retention-runtime-owned-memory-lifecycle.md) —
  finite retention and Runtime-owned bounded recovery/cleanup/shutdown.

The formal review is
[`RFC-0030-agent-memory-threat-model-review.md`](../security/RFC-0030-agent-memory-threat-model-review.md).

## Release validation

The release candidate must pass:

```text
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
python scripts/check_webhook_release.py
python scripts/check_inbound_release.py
python scripts/check_inference_release.py
python scripts/check_agent_release.py
python scripts/check_durable_agent_release.py
python scripts/check_multi_agent_release.py
python scripts/check_agent_memory_release.py
```

The agent-memory gate validates RFC-0030 regressions, migration, ADR,
security-review, and release suites; inspects wheel and sdist metadata and contents;
rejects unsafe archive paths and sensitive files; rebuilds a wheel from the
validated sdist; and installs both wheel forms with `--no-deps --no-index` in
isolated offline environments before exercising packaged authoritative memory,
exact scope/resource names, deterministic retrieval, and deletion without
source-tree imports.
