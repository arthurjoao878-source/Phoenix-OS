# Phoenix OS 0.27.0

**Released:** 2026-07-29

Phoenix OS 0.27.0 accepts RFC-0027 and adds an optional Phoenix-owned agent loop
that can perform bounded model turns and explicitly authorized tool calls.

## Highlights

- Immutable agent, proposal, invocation, result, schema, limit, state, and safe
  error contracts.
- A closed-world server-owned tool registry with exact adapters and resource
  resolvers.
- Deterministic network-free model-turn and read-only or side-effecting fake
  tools for security and packaging tests.
- Independent authorization for `agent.run`, every RFC-0026 `model.infer` turn,
  and every exact `tool.invoke` call.
- Action-bound, actor-bound, short-lived, single-use approval records over the
  exact normalized invocation.
- A deterministic serial agent state machine with finite steps, turns, calls,
  bytes, tokens, queue, concurrency, duration, cancellation, and shutdown limits.
- Strict tool input and output validation with untrusted result isolation.
- Optional `RuntimeAssembler` composition, deterministic startup rollback,
  content-free observability, safe health, and maintainer administration.
- Migration, rollback, ADR, threat-review, and isolated package validation
  documentation.

## Security

Agent execution is disabled by default. Installing or importing v0.27.0 creates
no assistant, tool, permission, approval, run, model call, worker, listener,
network access, filesystem access, shell access, operating-system action, or
persistent agent state.

Model output is untrusted data and receives no direct tool authority. The outer
agent authorization does not authorize nested work: every model turn and tool
call receives a new independent policy decision. Tool resources are resolved by
trusted server-side code after strict argument validation and cannot be supplied
by the model.

Tool arguments and results fail closed under Phoenix-owned bounded schemas and
canonical codecs. Unknown properties, duplicate keys, malformed Unicode,
non-finite numbers, unsupported structures, and oversized values are rejected.
Tool output remains untrusted when returned to the next model turn.

Approvals bind the exact tool, resource, canonical argument digest, run, step,
call, actor, and expiry. They are single-use and replay-resistant. Any mutation
invalidates the approval.

The Runtime performs no transparent retry of model or tool execution. Ambiguous
external failures are reported as indeterminate rather than repeated. Phoenix
does not claim exactly-once side effects.

Audit, metrics, logs, health, administration, and Event Bus observations exclude
prompts, model responses, raw arguments, tool results, credentials, secret
references, approval tokens, endpoint details, external response bodies, and raw
exceptions. Events use fixed Phoenix-owned types and empty payloads.

Installed tool adapters remain trusted deployment code. RFC-0027 does not add a
generic shell, unrestricted HTTP client, unrestricted filesystem tool,
operating-system controller, hostile-code sandbox, autonomous scheduler,
persistent agent memory, or machine administration API.

## Compatibility and migration

When agent configuration is omitted, Phoenix OS preserves v0.26.0 Runtime,
inference, Control Plane, Dashboard, service-account, webhook, inbound-event,
session, job, workflow, audit, secret, Event Bus, network, TLS, and persistence
behavior.

Inference remains independently configurable when the agent subsystem is
disabled. Existing principals and service accounts receive no agent, model, or
tool authority automatically.

Follow the staged
[v0.26.0 to v0.27.0 agent migration guide](../migrations/v0.26.0-to-v0.27.0-agent.md)
for deterministic validation, registry review, exact policy and approval setup,
conservative limits, content-free observation, canary enablement, and rollback.

## Architecture decisions

RFC-0027 is supported by five accepted records:

- [ADR-0016](../adrs/ADR-0016-server-owned-tool-registry-and-strict-agent-schemas.md)
  — server-owned tool allowlisting and strict schemas.
- [ADR-0017](../adrs/ADR-0017-independent-agent-model-tool-authorization-and-exact-approvals.md)
  — independent run, model, and tool policy plus exact approvals.
- [ADR-0018](../adrs/ADR-0018-bounded-serial-agent-loop-and-no-transparent-retry.md)
  — bounded serial execution without hidden retry.
- [ADR-0019](../adrs/ADR-0019-untrusted-tool-results-and-content-free-agent-observability.md)
  — untrusted results and content-free safe output.
- [ADR-0020](../adrs/ADR-0020-opt-in-agent-runtime-and-bounded-lifecycle.md)
  — optional Runtime ownership, rollback, and bounded shutdown.

The formal threat and invariant review is
[`RFC-0027-agent-threat-model-review.md`](../security/RFC-0027-agent-threat-model-review.md).

## Release validation

The release commit must pass:

```text
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
python scripts/check_webhook_release.py
python scripts/check_inbound_release.py
python scripts/check_inference_release.py
python scripts/check_agent_release.py
```

The agent release gate reruns the selected agent security, execution, Runtime,
observability, migration, ADR, RFC, and release suites. It inspects wheel and
sdist metadata and contents, rejects unsafe archive paths and sensitive files,
rebuilds a wheel from the sdist, and installs both wheels with no dependency or
index access in isolated environments before executing the packaged agent
surface without source-tree imports.
