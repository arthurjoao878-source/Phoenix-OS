# Phoenix OS 0.28.0

**Prepared:** 2026-08-10

Phoenix OS 0.28.0 prepares RFC-0028 durable agent runs for final publication.
The subsystem adds bounded restart-resumable checkpoints, fenced recovery,
explicit indeterminate-attempt reconciliation, optional protected payloads,
finite retention, content-free operations, and Runtime-owned lifecycle control.

The release remains untagged until the final publication step completes the
`v0.28.0` tag, wheel and sdist assets, and `SHA256SUMS`.

## Highlights

- Immutable durable-run, checkpoint, attempt, lease, reconciliation, retention,
  and safe error contracts.
- Strict canonical checkpoint encoding with digest chaining, monotonic sequence
  enforcement, run binding, version checks, and fail-closed decoding.
- Atomic in-memory and SQLite reference stores with optimistic versions,
  fenced leases, bounded history, and deterministic recovery candidates.
- Fresh exact `agent.resume`, RFC-0026 `model.infer`, `tool.invoke`, and
  `agent.reconcile` authorization at the current state.
- Explicit indeterminate model/tool attempt records with no transparent retry
  and reviewed reconciliation rather than exactly-once claims.
- Metadata-only persistence by default and opt-in authenticated protected
  payloads with bounded sizes, versioned keys, namespace binding, and finite
  retention.
- Bounded recovery, cancellation, shutdown, retention, cleanup, tombstones,
  content-free observability, and maintainer administration.
- Named durable-agent release gate with wheel/sdist inspection, wheel rebuild,
  and isolated offline installation smoke tests.

## Security

Durable-agent execution remains disabled unless explicitly configured. Enabling
the feature grants no run, tool, permission, approval, worker, payload,
schedule, credential, external access, or machine-administration authority
automatically.

A checkpoint is data, not authority. Persisted policy decisions are
informational only. Resume, model, tool, approval, and reconciliation decisions
are revalidated against current configuration, registry, schemas, limits,
policy, lease ownership, and fencing generation.

Stale workers cannot mutate after lease replacement because every guarded write
uses the current fenced lease generation and expected run version. Corrupt,
truncated, oversized, unsupported, non-canonical, rolled-back, duplicate, or
cross-run checkpoint state fails closed.

Phoenix performs no transparent retry of an indeterminate model or tool attempt
and does not claim exactly-once external side effects. Idempotency keys may
reduce duplicate risk but do not replace reviewed reconciliation evidence.

Protected content is absent by default. When explicitly enabled, protected
payloads use authenticated protection, versioned keys, strict size bounds,
opaque server-owned references, exact checkpoint binding, and finite retention.
Plaintext prompts, responses, raw arguments, results, credentials, approval
tokens, protected payloads, encryption metadata, and raw exceptions remain
excluded from safe logs, audit, metrics, health, events, filenames, policy
resources, and administration responses.

Installed adapters remain trusted deployment code; RFC-0028 is not a hostile
code sandbox and does not add generic shell, filesystem, network, browser,
desktop, or operating-system automation authority.

## Compatibility and migration

When durable-agent configuration is omitted, Phoenix OS preserves v0.27.0 agent,
inference, Runtime, Control Plane, Dashboard, service-account, webhook,
inbound-event, session, job, workflow, audit, secret, Event Bus, network, TLS,
and persistence behavior.

Upgrade creates no durable run, checkpoint, payload, key lease, recovery worker,
permission, approval, model call, tool call, or external access automatically.
Ordinary in-memory RFC-0027 agent execution and RFC-0026 inference remain
independently configurable.

Follow the staged
[v0.27.0 to v0.28.0 durable-agent migration guide](../migrations/v0.27.0-to-v0.28.0-durable-agent.md)
for disabled-first installation, deterministic storage/codec checks,
metadata-only canaries, optional protected-content validation, exact
authorization setup, conservative recovery limits, retention, observation, and
disable-first rollback.

## Architecture decisions

RFC-0028 is supported by five accepted records:

- [ADR-0021](../adrs/ADR-0021-untrusted-canonical-chained-durable-checkpoints.md)
  — untrusted canonical chained checkpoint data, never persisted authority.
- [ADR-0022](../adrs/ADR-0022-fenced-leases-and-conditional-durable-mutation.md)
  — fenced leases and conditional durable mutation.
- [ADR-0023](../adrs/ADR-0023-controlled-recovery-and-explicit-indeterminate-reconciliation.md)
  — controlled recovery and explicit indeterminate reconciliation.
- [ADR-0024](../adrs/ADR-0024-opt-in-protected-payloads-and-content-free-durable-operations.md)
  — opt-in protected payloads and content-free durable operations.
- [ADR-0025](../adrs/ADR-0025-opt-in-runtime-owned-durable-lifecycle-retention-and-administration.md)
  — opt-in Runtime lifecycle, bounded retention, and separated administration.

The formal review is
[`RFC-0028-durable-agent-threat-model-review.md`](../security/RFC-0028-durable-agent-threat-model-review.md).

## Release validation

The release candidate must pass:

```text
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
python scripts/check_webhook_release.py
python scripts/check_inbound_release.py
python scripts/check_inference_release.py
python scripts/check_agent_release.py
python scripts/check_durable_agent_release.py
```

The durable-agent gate validates the RFC-0028 regression, migration, ADR,
security-review, and release suites; inspects wheel and sdist metadata and
contents; rejects unsafe archive paths and sensitive files; rebuilds a wheel
from the validated sdist; and installs both wheel forms with `--no-deps
--no-index` in isolated offline environments before executing the packaged
durable surface without source-tree imports.
