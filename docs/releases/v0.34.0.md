# Phoenix OS 0.34.0

**Released:** 2026-08-24

Phoenix OS 0.34.0 accepts RFC-0034, Secure Network Egress and Controlled HTTP
Operations.

## Highlights

- Optional controlled HTTP egress through immutable server-owned profiles and stable Phoenix-owned operation identifiers.
- Canonical generation-bound `network.http.request` authority with RFC-0033 freshness and non-amplification guarantees.
- Bounded DNS/IP admission, literal destination pinning, verified hosted TLS, no ambient proxies, and no automatic redirects.
- One-shot bounded HTTP/1.1 exchange with no transparent retry after request bytes may have started.
- Exact-version Secrets Vault credential bindings whose plaintext material is revealed only at the final transport boundary.
- Reviewed `tool.invoke -> network.http.request` composition preserving both independent authority boundaries.
- Dedicated SSRF, DNS-rebinding, stale-profile, credential, cancellation, confused-deputy, redaction, lifecycle, and package-release evidence.
- Optional Runtime ownership plus content-free best-effort observation and separately authorized bounded health inspection.

## Security

Remote data is data. Network effects require fresh, exact, server-owned authority.
Callers select only profile and operation IDs plus bounded request body data. They
cannot choose URL, scheme, host, port, DNS, proxy, TLS, redirect policy,
credential, literal destination, method, request target, or arbitrary header.

DNS answers are bounded and every returned address must satisfy the active
policy. Connections use only admitted literals. Hosted destinations retain the
canonical hostname for TLS SNI and certificate validation. Ambient proxies are
ignored and redirects are returned only as bounded untrusted response data.

After the final attacker-controlled network wait, Phoenix revalidates current
RFC-0033 subject state, exact `network.http.request` authority, exact credential
lease when configured, cancellation/deadline, complete current profile/operation
state, and pinned destination admission before the one-shot exchange.

Model-originated network work retains independent `tool.invoke` and
`network.http.request` admission. Neither boundary implies the other, and network
authority does not imply browser, webhook, inference, memory, workspace, host,
model, or other protected authority.

Potentially effectful requests are never transparently replayed after request
bytes may have started. Ambiguous post-send outcomes remain indeterminate.

## Compatibility and migration

Phoenix OS 0.33.0 behavior is preserved when network-egress configuration is
omitted. Upgrade creates no service, profile, operation, permission, credential
binding, request, DNS lookup, socket, or remote effect automatically.
Existing webhook and model-provider networking remains independently
authoritative and is not migrated through RFC-0034.

See `docs/migrations/v0.33.0-to-v0.34.0-secure-network-egress.md` for rollout and rollback guidance.

## Release validation

The release must pass:

```bash
ruff check .
ruff format --check .
mypy
pytest
python scripts/check_network_egress_release.py
```

The dedicated gate reruns RFC-0034 network-egress and relevant agent/authority
integration regressions, validates the exact reviewed package surface and release
documents, builds/inspects wheel and sdist, rebuilds a wheel from the validated
sdist, and installs both wheel forms with `--no-deps --no-index`.
The installed-package smoke performs no DNS query, socket connection, HTTP
exchange, credential lease, policy mutation, or remote effect.
The complete GitHub Actions Python 3.12/3.13 matrix must be green for the exact
release commit before tag or publication operations.
