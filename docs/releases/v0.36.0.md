# Phoenix OS 0.36.0

**Released:** 2026-08-28

Phoenix OS 0.36.0 accepts RFC-0036, Secure Integrated Agent Execution and
End-to-End Orchestration.

## Highlights

- Optional Phoenix-owned task-level orchestration bound to immutable task identity/digest and exact server-owned integrated execution profile generation.
- Advisory bounded planning through the existing RFC-0027 agent/tool model, with `integrated.plan.update` as data rather than authority.
- Exact server-owned `LOCAL_TRANSFORM` and `DOWNSTREAM_BRIDGE` tool bindings that preserve independent `tool.invoke` and downstream canonical authority.
- Conservative exact provenance propagation, finite server-owned cross-subsystem data-flow routes, and explicit authenticated `USER_RESULT` disclosure admission.
- Sequential effectful execution with bounded budgets, parent-bounded deadlines, cancellation propagation, no transparent retry, and RFC-0028 reconciliation for `INDETERMINATE` effects.
- Optional durable orchestration projection and recovery that retain exact task/profile binding while requiring fresh current authorization and sufficient reviewed planning context.
- Content-free best-effort observation plus separately authorized bounded redacted health/run inspection.
- Dedicated deterministic adversarial, package-boundary, rebuilt-sdist, isolated-install, and network-free end-to-end release evidence.

## Security

Task text, model planning/output, tool proposals/results, browser/network content,
memory/workspace/clipboard content, child-agent results, and persisted orchestration
state remain untrusted data. None can manufacture Phoenix authority.

Starting an integrated task does not authorize model inference, tool invocation, or
any downstream memory, workspace, host, network, browser, delegation, or durable
operation. Model-originated protected work retains `tool.invoke` and the exact
current downstream canonical authority. The planner cannot choose credentials,
profiles, policy resources, approvals, or authority-bearing destinations.

Every integrated value carries bounded exact provenance atoms. Model turns, local
transforms, bridge transformations, and planning normalization conservatively
preserve provenance. Phoenix OS 0.36.0 provides no provenance declassification
primitive; overflow fails closed rather than truncating or laundering provenance.

Cross-subsystem disclosure is admitted by finite server-owned data-flow routes
before approval consumption or downstream effect admission. Final user-visible
output crosses the explicit `USER_RESULT` sink for an audience derived from trusted
task admission and authenticated context.

Potentially effectful integrated work is sequential and is never transparently
retried after effect start may have occurred. Ambiguous outcomes remain
`INDETERMINATE` and enter the existing RFC-0028 reconciliation path when durability
is enabled.

Routine telemetry is content-free. Health requires
`integrated.agent.health.read`; separately authorized exact-run inspection requires
`integrated.agent.inspection.read` and returns only reviewed bounded redacted
metadata.

## Compatibility and migration

Phoenix OS 0.35.0 behavior is preserved when integrated-execution configuration is
omitted. Upgrade creates no integrated task, profile, planner, tool binding,
downstream bridge, data-flow route, durable projection, observer, administrator,
permission, approval, credential, worker, browser session, network request, host
effect, memory operation, workspace mutation, or external authority automatically.

Existing RFC-0026 through RFC-0035 model, agent, durable, delegation, memory,
workspace, host, effective-authority, network, and browser boundaries remain
independently authoritative. Integrated execution coordinates those services; it
does not replace their identities, authorizers, freshness rules, limits, approvals,
or effect semantics.

See
`docs/migrations/v0.35.0-to-v0.36.0-secure-integrated-agent-execution.md` for
disabled-first rollout, profile/tool binding, provenance/data-flow, recovery,
observation/administration, validation, and rollback guidance.

## Release validation

The release must pass:

```bash
ruff check .
ruff format --check .
mypy
pytest
python scripts/check_integrated_agent_release.py
```

The dedicated integrated-agent gate reruns the complete integrated regression
surface plus the v0.36.0 release specification, rechecks the 102-invariant threat
review and frozen package surface, executes deterministic adversarial E2E with
external network access denied, validates wheel and sdist contents/metadata,
rebuilds a wheel from the validated sdist, and installs both wheel forms with
`--no-deps --no-index` in isolated environments.

The normal GitHub Actions Python 3.12/3.13 matrix must be green for the exact
release commit before tag or publication operations.
