# Phoenix OS 0.35.0

**Released:** 2026-08-26

Phoenix OS 0.35.0 accepts RFC-0035, Secure Browser Automation and Controlled Web
Interaction.

## Highlights

- Optional browser automation through immutable server-owned profiles and navigation targets.
- Finite exact browser actions with opaque Phoenix-owned session, page, revision, and element identities.
- Bounded page observation with no raw HTML/DOM surface and separate fresh `browser.page.read` disclosure authority.
- Controlled top-level navigation and click/form effects with exact origin policy, bounded DNS/IP admission, and finite redirect re-admission.
- Zero-effect adapter preparation followed by final current-authority, stale-identity, destination, cancellation, and deadline revalidation before commit.
- Reviewed `tool.invoke` to exact browser-action composition with server-owned bindings and no authority amplification.
- Optional Runtime ownership, bounded shutdown, content-free best-effort observation, and separately authorized `browser.health.read` inspection.
- Dedicated stale-identity, SSRF, confused-deputy, cancellation, retry, redaction, lifecycle, and package-release evidence.

## Security

Web content is data. Browser state is data. Neither grants Phoenix authority.
Browser authority remains independent from `tool.invoke`, `network.http.request`,
host, workspace, memory, model, webhook, inference, and other protected
boundaries.

Callers and models select only Phoenix-owned profile, target, session, page,
revision, and opaque element identities plus bounded operation input where
applicable. They cannot select arbitrary URLs, selectors, XPath, coordinates,
JavaScript, browser executables, profiles, proxies, cookies, credentials, native
handles, or host paths.

Hosted origins require verified HTTPS and plain HTTP is limited to explicit
loopback mode. Every DNS answer must pass current destination policy, unsafe mixed
answer sets fail closed, redirects are finite, and every redirect destination is
re-admitted. Browser traffic does not silently acquire `network.http.request`.

After the final attacker-controlled preparation wait, Phoenix revalidates the
current structural subject, profile generation, session/page/revision/element
identity, exact browser action and intent, independent `tool.invoke` authority
when model-originated, destination admission when remote effects are possible,
and cancellation/deadline state. No new attacker-controlled blocking wait is
inserted before protected commit.

JavaScript, autonomous/background browser networking, automatic subresources,
iframes, popups, multiple pages, downloads, uploads, persistent browser storage,
persistent cookies, and production browser engines remain outside the v0.35.0
core contract. Potentially effectful browser operations are never transparently
retried after an effect may have started; ambiguous outcomes remain
`INDETERMINATE`.

## Compatibility and migration

Phoenix OS 0.34.0 behavior is preserved when browser-automation configuration is
omitted. Upgrade creates no browser service, profile, engine, process, session,
page, cookie, navigation, permission, approval, tool binding, DNS lookup, network
request, host effect, workspace transfer, worker, or remote effect automatically.

Existing RFC-0034 controlled HTTP egress, webhook delivery, inference transport,
host automation, workspaces, memory, and agent execution retain their independent
canonical authorizers and are not silently migrated through browser automation.

Phoenix OS does not bundle a production browser engine. Any deployment adapter
must independently satisfy the reviewed zero-effect prepare/commit,
destination-admission, JavaScript-disabled, subresource-blocked, stale-identity,
content-minimization, and no-transparent-retry contracts.

See `docs/migrations/v0.34.0-to-v0.35.0-secure-browser-automation.md` for staged
rollout, adapter, authority, lifecycle, observability, failure, and rollback
guidance.

## Release validation

The release must pass:

```bash
ruff check .
ruff format --check .
mypy
pytest
python scripts/check_browser_automation_release.py
```

The dedicated browser gate reruns the complete browser-automation regression
surface plus RFC-0035, validates the exact reviewed browser package surface and
required hardening documents, builds and inspects wheel and sdist, rebuilds a
wheel from the validated sdist, and installs both wheel forms with
`--no-deps --no-index`.

The installed-package smoke performs no DNS query, socket connection, HTTP
exchange, browser process launch, navigation, click, fill, page disclosure,
credential access, policy mutation, or external effect. The complete GitHub
Actions Python 3.12/3.13 matrix must be green for the exact release commit before
tag or publication operations.
