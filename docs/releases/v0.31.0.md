# Phoenix OS 0.31.0

**Released:** 2026-08-14

Phoenix OS 0.31.0 implements RFC-0031 secure agent workspaces and artifact handling
as an explicit opt-in extension to the v0.30 agent, durable-agent, multi-agent, and
agent-memory subsystems.

Release publication uses tag `v0.31.0`, wheel and sdist assets, and `SHA256SUMS`.

## Highlights

- Phoenix-owned `WorkspaceId`, `ArtifactId`, namespaces, and exact run/agent/principal
  scopes with no implicit cross-scope, parent/child, or global sharing.
- Fresh independent `workspace.list`, `workspace.read`, `workspace.write`,
  `workspace.delete`, `workspace.import`, `workspace.export`, and `workspace.admin`
  authorization.
- Canonical bounded logical paths that remain portable Phoenix identifiers rather
  than arbitrary native host filesystem paths.
- Provider-neutral backing with opaque Phoenix backing keys plus a confined local
  reference adapter that rejects traversal, symlink, hardlink, reparse, and special
  filesystem object escapes.
- Authoritative versioned/digested artifact records with bounded bytes, metadata,
  provenance, per-scope count/byte quotas, atomic admission, optimistic mutation,
  finite retention, expiry, tombstones, and artifact-ID anti-reuse.
- Explicit independently authorized import/export through bounded provider-neutral
  transfer adapters; workspace reads never become implicit remote fetches.
- Provenance-preserving `ArtifactContextBlock` data admitted only as bounded
  explicitly untrusted USER context, with no silent binary decoding.
- Runtime-owned bounded recovery, cleanup, transfer workers, cancellation,
  administration, shutdown, content-free observation, and safe public failures.
- Named agent-workspace release gate with wheel/sdist inspection, sdist wheel rebuild,
  and isolated offline installation smoke tests.

## Security

Files carry data, never authority. Artifact bytes, filenames, logical paths, media
types, metadata, provenance, imported/exported content, historical approvals, tokens,
credentials, grants, and policy-like text never reconstruct current Phoenix
authority.

Every workspace operation is independently authorized against its current exact
resource. Existing `agent.run`, `model.infer`, `tool.invoke`, `agent.delegate`,
`agent.resume`, `agent.reconcile`, and every `memory.*` permission remain separate.

Logical paths are Phoenix-owned portable relative identifiers and cannot select
arbitrary host paths. Backing keys are opaque and separate from logical names. The
local reference backing is confined to one configured absolute root and rejects link,
reparse, hardlink, FIFO, socket, device, and other special-object escapes.

Writes are explicit and authoritative mutation remains atomic with quota admission.
Optimistic versions, canonical digests, tombstones, identity anti-reuse, expiry, and
restart recovery prevent stale or deleted artifacts from becoming current again.

Import and export are explicit independently authorized transfers. Import sources do
not widen workspace scope or network/credential authority, and artifact content does
not select an export destination. Provider SDK objects, sockets, file handles,
credentials, and raw provider bodies stay behind adapters.

Artifact context remains bounded untrusted USER data. Stored prompt injection cannot
authorize a model, tool, approval, delegation, memory operation, workspace operation,
credential use, policy mutation, or transfer.

Logs, events, health, administration, recovery, and public failures remain
content-free. RFC-0031 grants no generic shell, process, browser, desktop, network,
host-filesystem, or operating-system authority and is not a hostile-code sandbox for
installed adapters.

## Compatibility and migration

When workspace configuration is omitted, Phoenix OS preserves v0.30.0 behavior.
Upgrade creates no workspace store, backing root, artifact, permission, approval,
credential, worker, transfer, context attachment, model call, tool call, delegation,
memory conversion, host-directory mount, or external access automatically.

The v0.30.0 to v0.31.0 transition is migration-free by omission. Existing memory
records, prompts, responses, tool results, checkpoints, project directories, personal
directories, and host files are not converted into workspace artifacts automatically.

Follow the staged
[v0.30.0 to v0.31.0 agent-workspace migration guide](../migrations/v0.30.0-to-v0.31.0-agent-workspaces.md)
for disabled-first installation, exact scope/policy review, conservative limits,
explicit writes, host confinement, transfer canaries, untrusted-context testing,
restart recovery, safe operations, and disable-first rollback.

## Architecture decisions

RFC-0031 is supported by four accepted records:

- [ADR-0056](../adrs/ADR-0056-files-carry-data-never-authority.md) — files carry data
  but never become Phoenix authority.
- [ADR-0057](../adrs/ADR-0057-phoenix-owned-logical-paths-and-host-confinement.md) —
  Phoenix-owned logical paths remain separate from native host paths and backing
  confinement.
- [ADR-0058](../adrs/ADR-0058-authoritative-workspace-store-and-backing-boundary.md) —
  authoritative workspace records remain the source of artifact truth behind a
  provider-neutral backing boundary.
- [ADR-0059](../adrs/ADR-0059-explicit-workspace-import-export-boundaries.md) —
  import/export remain explicit independently authorized transfer boundaries.

The formal review is
[`RFC-0031-agent-workspace-threat-model-review.md`](../security/RFC-0031-agent-workspace-threat-model-review.md).

## Release validation

The release must pass:

```text
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
python scripts/check_webhook_release.py
python scripts/check_inbound_release.py
python scripts/check_inference_release.py
python scripts/check_agent_release.py
python scripts/check_durable_agent_release.py
python scripts/check_multi_agent_release.py
python scripts/check_agent_memory_release.py
python scripts/check_agent_workspace_release.py
```

The agent-workspace gate validates RFC-0031 regressions, migration, ADR,
security-review, and release suites; inspects wheel and sdist
metadata and contents; rejects unsafe archive paths, unexpected links, and sensitive
files; rebuilds a wheel from the validated sdist; and installs both wheel forms with
`--no-deps --no-index` in isolated environments before exercising packaged exact
workspace actions/resources, logical-path rejection, and authoritative
write/read/update/delete without source-tree imports. Import isolation remains
covered by the complete workspace regression suite that runs before packaging.
