# Migrating from Phoenix OS v0.24.0 to v0.25.0 inbound events

This guide covers the opt-in secure inbound event gateway introduced for
Phoenix OS v0.25.0. It is intended for deployments that already run v0.24.0
webhooks, jobs, workflows, audit, secrets, Event Bus, service accounts,
plugins, or the Control Plane.

The migration is additive. Existing webhook subscriptions are not converted
into inbound sources, existing Event Bus publishers are not trusted as external
sources, and no source, route, schema, HMAC key, service-account grant, replay
record, accepted event, or network permission is created automatically.

## Compatibility boundary

`RuntimeAssembler` keeps inbound events disabled unless
`inbound_events_enabled=True` is supplied. A v0.24.0 assembly can therefore be
upgraded without adding inbound arguments and should preserve its previous
service map, component order, listener, Dashboard, authentication, and
persistence behavior.

Do not pass inbound repositories, normalizers, publisher configuration,
admission policy, HMAC context, or machine-administration options while
`inbound_events_enabled=False`. Phoenix rejects that ambiguous state instead of
silently retaining inactive security-sensitive configuration.

A safe rollout uses conditional keyword arguments:

```python
inbound_options: dict[str, object] = {}

if settings.inbound_events_enabled:
    inbound_options = {
        "inbound_events_enabled": True,
        "inbound_event_normalizers": (
            ReleaseCompletedNormalizer(),
        ),
    }

assembler = RuntimeAssembler(
    kernel=kernel,
    events=events,
    capabilities=capabilities,
    configuration=configuration,
    secrets=secrets,
    policy=policy,
    control_plane_authenticator=control_plane_authenticator,
    **inbound_options,
)
```

When the feature flag is false, omit all inbound-specific arguments rather than
passing dormant production configuration.

## Before upgrading

Complete these checks before enabling external ingress:

1. Run the v0.24.0 quality gate and record the baseline.
2. Inventory the external event producers that genuinely require access.
3. Define one reviewed schema and normalizer for every accepted external event
   type and schema version.
4. Decide whether source configuration, replay evidence, accepted events,
   attempts, retry schedules, receipts, and dead letters must survive restart.
5. Choose HMAC-SHA-256 or RFC-0023 service-account authentication separately for
   each source.
6. Provision exact versioned HMAC material when HMAC is selected.
7. Review the existing Control Plane listener, exposure, TLS or mTLS, CIDR, proxy,
   Host, origin, and request-size policies.
8. Choose human administration, service-account administration, or neither.
9. Prepare a rollback that disables sources before disabling the Runtime-owned
   subsystem.
10. Confirm that external producers can retain stable request, event, and nonce
    identifiers for retries.

Do not treat unrestricted external JSON as an internal Event Bus event. The
reviewed normalizer is the allowlisting boundary.

## Step 1: upgrade without enabling inbound events

Upgrade the package or checked-out source while leaving the existing
`RuntimeAssembler` call unchanged. Validate the unchanged assembly first:

```powershell
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
```

Start and stop the application once with inbound events absent. Verify that no
service whose name begins with `inbound` and no
`control_plane.inbound-*` service appears in the Runtime service map or
component snapshot.

Confirm that:

- existing webhook subscriptions still deliver unchanged;
- the Control Plane binds the same listener and network policy;
- existing service accounts have no `inbound_event.*` scopes;
- no `/v1/control-plane/inbound/<source-name>` route exists;
- no inbound State Store keys or in-memory repositories are created.

This deployment proves v0.24.0 compatibility before any new ingress authority is
introduced.

## Step 2: define a reviewed schema and normalizer

Each normalizer declares exactly one `InboundEventSchema`. The schema maps one
external event name and version to one code-reviewed internal Event Bus event
name.

```python
from collections.abc import Mapping

from phoenix_os.inbound_events import InboundEventSchema


class ReleaseCompletedNormalizer:
    schema = InboundEventSchema(
        event_type="release.completed",
        event_schema_version=1,
        internal_event_type="external.release.completed",
        required_fields=frozenset(
            {
                "release",
                "status",
            }
        ),
        optional_fields=frozenset(
            {
                "repository",
            }
        ),
        reject_unknown_fields=True,
        max_raw_body_bytes=64 * 1024,
        max_normalized_payload_bytes=16 * 1024,
    )

    def normalize(
        self,
        payload: Mapping[str, object],
    ) -> Mapping[str, object]:
        release = payload.get("release")
        status = payload.get("status")
        repository = payload.get("repository")

        if not isinstance(release, str) or not release:
            raise ValueError("release.completed requires release")
        if status not in {"completed", "failed"}:
            raise ValueError("release.completed status is invalid")
        if repository is not None and not isinstance(repository, str):
            raise ValueError("release.completed repository is invalid")

        normalized: dict[str, object] = {
            "release": release,
            "status": status,
        }
        if repository is not None:
            normalized["repository"] = repository
        return normalized
```

Normalizer review should reject:

- credentials, bearer tokens, cookies, CSRF or step-up proofs, HMAC signatures,
  nonces, and secret references;
- unrestricted request objects or raw request bodies;
- arbitrary caller-selected internal Event Bus event names;
- local filesystem paths, proxy chains, certificate material, and internal
  exception text;
- fields not required by the internal event contract;
- unbounded strings, mappings, sequences, depth, and normalized payloads;
- nondeterministic values that are not facts from the accepted external event.

Changing a schema or normalizer is a contract change. Prefer a new external
schema version or event type rather than silently changing the meaning of an
existing accepted payload.

## Step 3: review the shared listener boundary

Inbound events do not create a second socket. They reuse the existing Control
Plane listener and inherit its listener lifecycle, Host validation, request
limits, client rate limits, CIDR policy, proxy identity rules, TLS or mTLS,
remote admission, and shutdown order.

A local-only migration may keep the existing loopback listener. Remote ingress
requires the reviewed RFC-0022 boundary:

- a fixed nonzero port;
- native TLS;
- HTTPS public origin;
- Secure cookies for browser administration;
- explicit allowed client networks;
- explicit trusted proxy networks when proxy headers are enabled;
- durable operator mode;
- bounded client connections and request rates.

Enabling a source never changes listener binding, certificate material,
trusted-proxy configuration, or allowed networks. Change network exposure as a
separate reviewed operation.

The ingress path is exact and source-derived:

```text
/v1/control-plane/inbound/<source-name>
```

No wildcard source route is registered. Disabled and revoked sources have no
active ingress route.

## Step 4: choose repository durability

When no inbound repositories are supplied, `RuntimeAssembler` chooses a
coordinated repository trio:

- with a default `StateStore`, Phoenix creates State Store-backed source, event,
  and replay repositories;
- without a State Store, Phoenix creates bounded in-memory repositories;
- explicitly supplied repositories must include all three repositories.

The trio must share one durability and lifecycle decision. Do not mix an
in-memory replay repository with durable accepted events or durable sources.

In-memory repositories lose source configuration, replay evidence, accepted
events, receipts, publication attempts, retry schedules, and dead-letter state
when the process exits. Use them only for tests, demonstrations, or intentionally
ephemeral deployments.

State Store-backed repositories borrow the Runtime-owned State Store. Stopping
inbound events closes repository access but does not authorize deletion of the
underlying records.

Default Runtime capacities are:

- 256 sources;
- 4096 accepted events;
- 16,384 replay reservations.

Review capacity, retention, State Store limits, and expected retry volume before
production rollout.

## Step 5: provision an exact HMAC key version

HMAC sources reference an exact immutable `SecretRef`. Create the key through
`SecretsManager` and retain only the returned versioned reference.

```python
import os

from phoenix_os.configuration import SecretValue
from phoenix_os.policy import PrincipalType, SecurityContext
from phoenix_os.secrets import SecretRef, SecretsManager


secrets = SecretsManager()

bootstrap_context = SecurityContext(
    principal="migration:inbound-bootstrap",
    principal_type=PrincipalType.SYSTEM,
    authenticated=True,
    permissions=frozenset({"secret.create"}),
)

created = await secrets.create(
    SecretRef("release-inbound", "integrations"),
    SecretValue(os.urandom(32)),
    bootstrap_context,
)

inbound_hmac_ref = created.ref
```

`InboundHmacPolicy` rejects an unversioned reference. Never print, log, serialize,
persist in ordinary configuration, or place the plaintext key in a source
record. Persist only the exact `SecretRef`.

The default Runtime HMAC identity is the authenticated service principal
`phoenix.inbound`. A central secret policy must permit this principal, or the
explicitly supplied `inbound_hmac_context`, to perform the exact secret lease
and lease-revocation operations required for verification.

Keep a predecessor key version only during an explicit bounded rotation window.
Remove the predecessor after the window expires and external producers have
moved to the new version.

## Step 6: enable the Runtime with no sources

A minimal opt-in assembly requires:

- `SecretsManager`;
- `PolicyEngine`;
- at least one reviewed normalizer;
- an existing Control Plane listener.

```python
from phoenix_os.configuration import RuntimeAssembler


assembler = RuntimeAssembler(
    kernel=kernel,
    events=events,
    capabilities=capabilities,
    configuration=configuration,
    state=state_store,
    secrets=secrets,
    policy=policy,
    audit=audit,
    observability=observability,
    control_plane_authenticator=control_plane_authenticator,
    inbound_events_enabled=True,
    inbound_event_normalizers=(
        ReleaseCompletedNormalizer(),
    ),
)

runtime = await assembler.assemble()
await runtime.start()
```

Startup performs the security-sensitive order:

1. create or bind the coordinated repositories;
2. register reviewed schemas and normalizers;
3. validate every durable source against the registry;
4. recover interrupted publication work;
5. start the publisher worker;
6. start the recovery worker;
7. start the shared Control Plane listener last.

An empty source repository exposes no ingress route. Enabling the subsystem does
not make the listener accept arbitrary external events.

The Runtime exposes services such as:

```text
inbound
inbound.sources
inbound.events
inbound.replay
inbound.schemas
inbound.authentication
inbound.gateway
inbound.ingress
inbound.publisher
inbound.recovery
inbound.manager
inbound.owner
control_plane.inbound-http
```

## Step 7: create the first source while disabled

Human source creation requires durable operator mode and the exact Maintainer
permission. New sources are created disabled so their contract can be inspected
before any external request is accepted.

The Dashboard is the normal operator workflow. A reviewed bootstrap or test
harness may use the manager directly:

```python
from phoenix_os.inbound_events import (
    InboundHmacPolicy,
    InboundManager,
)
from phoenix_os.policy import PrincipalType, SecurityContext


manager = runtime.service("inbound.manager")
assert isinstance(manager, InboundManager)

maintainer = SecurityContext(
    principal="operator:migration",
    principal_type=PrincipalType.USER,
    authenticated=True,
    permissions=frozenset(
        {
            "inbound_event.source.create",
        }
    ),
)

source = await manager.create_source(
    maintainer,
    name="release.events",
    display_name="Release Events",
    authentication=InboundHmacPolicy(inbound_hmac_ref),
    event_types=frozenset(
        {
            "release.completed",
        }
    ),
    max_body_bytes=64 * 1024,
    max_header_bytes=8 * 1024,
    max_concurrency=4,
    requests_per_minute=60,
)

assert source.status.value == "disabled"
```

Inspect the source name, exact event types, authentication mode, key version,
body and header limits, timestamp skew, replay retention, concurrency, request
rate, retry policy, and revision before enablement.

Secret names, namespaces, authorization headers, signatures, raw bodies, and
protected digests are not part of the administrative view.

## Step 8: validate the producer contract

For HMAC-SHA-256 v1, the producer must send exactly one value for each required
header:

```text
Content-Type: application/json
X-Phoenix-Inbound-Request-Id: <stable request id>
X-Phoenix-Inbound-Event-Id: <stable source event id>
X-Phoenix-Inbound-Timestamp: <UTC timestamp>
X-Phoenix-Inbound-Nonce: <unique nonce>
X-Phoenix-Inbound-Signature: hmac-sha256-v1=<hex digest>
X-Phoenix-Inbound-Key-Version: <exact positive version>
```

`X-Phoenix-Correlation-Id` is optional and bounded.

The signature covers the source id, request id, source event id, timestamp,
nonce, and exact raw body bytes. The producer must sign the bytes it transmits
without reserializing JSON afterward.

HMAC requests must not contain `Authorization`. Service-account requests must
not contain HMAC signature or key-version headers. Browser cookies, CSRF proofs,
and human step-up proofs are rejected on ingress.

A safe staging test verifies:

- a valid request returns a stable receipt only after durable acceptance;
- repeating the same source event id with the same normalized digest returns the
  same stable receipt;
- repeating it with a different normalized digest returns a generic conflict;
- a repeated nonce or request id is rejected;
- stale and future timestamps are rejected;
- malformed, oversized, deeply nested, or unknown-field JSON is rejected;
- the external caller cannot select the internal Event Bus event name;
- no raw request body or plaintext credential appears in State Store, logs,
  audit, metrics, history, or administrative responses.

## Step 9: enable the canary source

Enable the source only after the disabled configuration and producer contract
have been reviewed.

```python
enable_context = SecurityContext(
    principal="operator:migration",
    principal_type=PrincipalType.USER,
    authenticated=True,
    permissions=frozenset(
        {
            "inbound_event.source.enable",
        }
    ),
)

enabled = await manager.enable_source(
    source.id,
    enable_context,
    expected_revision=source.revision,
)
```

The exact route becomes active only after the durable source update commits:

```text
/v1/control-plane/inbound/release.events
```

Send one controlled canary event and verify the receipt, normalized internal
event type, asynchronous publication, audit facts, metrics, and history. Then
exercise one retryable publication failure and one dead-letter outcome before
expanding production traffic.

## Step 10: optionally use RFC-0023 source authentication

Source authentication and machine administration are different decisions.

An ingress source may require an RFC-0023 token policy:

```python
from phoenix_os.inbound_events import InboundServiceAccountPolicy


source_authentication = InboundServiceAccountPolicy(
    resource="inbound-source:release-events",
)
```

The producer token must contain:

- scope `inbound_event.submit`;
- the exact source policy resource;
- a valid API-token identity;
- a fresh timestamp;
- a valid nonce;
- the request target and body digest used by replay protection;
- central policy approval.

The Runtime binds source authentication to the existing RFC-0023 security stack
only when service accounts are explicitly enabled. Existing service accounts
receive no inbound scope or resource automatically.

Do not grant `inbound_event.submit` to a token merely because it can administer
another Control Plane resource.

## Step 11: enable human administration

Durable operator mode wires the inbound manager into the existing protected
Control Plane and Dashboard.

Grant only the permissions required by each operator:

```text
inbound_event.source.read
inbound_event.source.create
inbound_event.source.update
inbound_event.source.authentication.update
inbound_event.source.disable
inbound_event.source.enable
inbound_event.source.revoke
inbound_event.source.rotate
inbound_event.event.read
inbound_event.receipt.read
inbound_event.health.read
inbound_event.dead_letter.redrive
```

Mutations require durable-session CSRF protection. Sensitive creation, update,
authentication, enable, revoke, rotation, and redrive operations require
action-bound step-up authentication. Disable remains CSRF-protected and does not
require step-up so operators can stop ingress quickly.

Do not grant `*` merely to simplify migration.

## Step 12: optionally enable machine administration

Machine administration is a separate opt-in:

```python
inbound_service_account_administration_enabled=True
```

It also requires:

- inbound events enabled;
- durable operator mode;
- service accounts enabled;
- a fixed secure `ControlPlaneNetworkPolicy`;
- a central `PolicyEngine`;
- the RFC-0023 authentication, replay, audit, and policy stack;
- exact `inbound_event.*` action scopes;
- gateway resource `inbound-machine`;
- a concrete source, event, or receipt resource.

Machine administration intentionally provides no aggregate source inventory,
source creation, aggregate event inventory, or health route. Concrete resources
use these forms:

```text
inbound-source:<uuid>
inbound-event:<uuid>
inbound-receipt:<uuid>
```

Browser cookies, CSRF proofs, and human step-up proofs are invalid at machine
routes.

Do not enable machine administration merely because a source uses
service-account authentication. External event submission and administrative
authority are separate permissions.

## Recommended production rollout

Use this order:

1. Upgrade with inbound events absent and validate unchanged v0.24.0 behavior.
2. Deploy reviewed normalizers, secret policy, and conditional configuration
   without enabling the production flag.
3. Provision the exact HMAC key version or reviewed service-account grants.
4. Enable the Runtime-owned subsystem with an empty source repository.
5. Inspect the `inbound` Runtime snapshot and repository health.
6. Create one source in the disabled state.
7. Review its schema, authentication, limits, retry policy, and route name.
8. Validate producer signing or RFC-0023 request construction in staging.
9. Enable one canary source.
10. Verify durable receipt and stable idempotency behavior.
11. Exercise replay, stale timestamp, malformed input, saturation, retry, dead
    letter, redrive, and restart recovery.
12. Confirm no plaintext credentials or unrestricted raw body are persisted.
13. Expand traffic gradually while watching safe metrics and audit facts.
14. Enable machine administration only after a separate security review.

## Rollback without losing state

Rollback should first remove ingress authority, not delete durable records.

1. Disable every active source through the Dashboard or protected manager.
2. Confirm that exact ingress routes are no longer registered.
3. Allow already accepted pending or retrying events to reach a reviewed terminal
   state, or record why they remain.
4. Retain exact HMAC key versions required by accepted records and rotation
   windows.
5. Export safe source, event, receipt, attempt, and dead-letter metadata required
   for the rollback record.
6. Stop the Runtime.
7. Remove `inbound_events_enabled` and every inbound-specific argument from the
   next assembly.
8. Preserve State Store records for a future re-enable or reviewed migration.
9. Start the downgraded or feature-disabled deployment and verify that no
   `inbound*` service or route exists.

Do not revoke or delete HMAC material while an enabled source, predecessor
window, or accepted work item still relies on that version. Do not delete replay
records merely to make a previously rejected request succeed.

A package downgrade to v0.24.0 cannot interpret v0.25.0 inbound records. Leave
those records untouched and inaccessible rather than rewriting them into another
subsystem.

## Health and acceptance checks

After enabling the subsystem:

```python
bundle = runtime.service("inbound")
manager = runtime.service("inbound.manager")

runtime_snapshot = await bundle.owner.snapshot()
manager_snapshot = await manager.snapshot()
publisher_snapshot = await bundle.publisher.snapshot()
recovery_snapshot = await bundle.recovery.snapshot()
```

Verify:

- the Runtime owner is running;
- every reviewed schema is registered;
- the number of active routes equals active durable sources;
- no route exists for disabled or revoked sources;
- repository capacities and closed flags are healthy;
- pending, publishing, retrying, dead-letter, and terminal counts are plausible;
- replay, conflict, authentication, schema, admission, and saturation counters
  match controlled tests;
- accepted event identity remains stable across retry and restart;
- audit and observability contain safe facts without credentials, signatures,
  nonces, protected digests, raw bodies, or internal exception text;
- the listener remains the existing Control Plane listener;
- service-account security is bound only when explicitly enabled.

Run the complete project gate after the migration configuration is in place:

```powershell
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
```

The final v0.25.0 release gate also builds and inspects wheel and sdist artifacts,
rebuilds a wheel from the sdist, installs both wheels in isolated offline
environments, and exercises the packaged inbound surface.

## Normative migration checks

Disabled and revoked sources have no active ingress route.

With a default `StateStore`, Phoenix creates State Store-backed source, event, and replay repositories.

External event submission and administrative authority are separate permissions.

The final package gate installs both wheels in isolated offline environments.

## Migration invariants

The migration is complete only when all of these remain true:

- inbound events are disabled by default;
- source repositories begin empty;
- every source is explicitly created and begins disabled;
- schemas and normalizers are code-reviewed;
- no webhook subscription is converted into a source;
- no existing service account receives an inbound scope or resource;
- no network permission is added automatically;
- only active exact source routes are exposed;
- every accepted event commits durably before success is returned;
- replay and source-event idempotency survive restart when State Store-backed;
- raw request bodies and plaintext credentials are never persisted;
- publication is asynchronous and at-least-once;
- retry and dead-letter state preserve the accepted event identity;
- human and machine administration remain separately authorized;
- rollback disables ingress before removing Runtime composition.
